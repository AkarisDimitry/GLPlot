Documentation for language models
=================================

``pip install glplot`` ships the documentation a language model needs to use the library correctly --
inside the package, so it does not depend on a copy of the repository, a website or the model's memory
of matplotlib (GLPlot is matplotlib-*like*, not identical).

It is reachable four ways, all serving the same text:

.. list-table::
   :header-rows: 1
   :widths: 30 70

   * - Where
     - How
   * - Command line
     - ``python -m glplot.llm guide [topic]``, ``search "<what you want>"``, ``describe <function>``,
       ``examples``, ``example <name>``, ``llms``, ``llms-full``, ``capabilities``, ``doctor``.
   * - Python
     - ``from glplot import llm`` then ``llm.guide("quickstart")``, ``llm.search_api("heatmap")``,
       ``llm.describe_api("hist2d")``, ``llm.example("line_plot")``, ``llm.llms_full_txt()``.
   * - MCP
     - The ``get_guide``, ``search_api``, ``get_api_doc``, ``get_example`` and ``server_info`` tools, plus
       ``glplot://`` resources and prompts. See :doc:`mcp-server`.
   * - One file
     - ``llms.txt`` at the repository root (a short entry point following the llmstxt.org convention) and
       ``python -m glplot.llm llms-full`` (every topic and the API reference in one document).

What is in it
-------------

* **Guides** (``glplot/llm/topics/*.md``): overview, quickstart, choosing a plot, axes and styling, 3-D,
  animation, controls, performance, export, matplotlib compatibility, the workstation, MCP and
  troubleshooting. They state the traps first -- ``show()`` blocks, set both axis limits or none,
  animation lives in ``glplot.animation``, output size is ``figsize x 240`` pixels.
* **An API index** (``glplot.llm.apiindex``): about 250 functions, introspected from the code, filed in
  13 categories, searchable by name or by words a person would use (``heatmap``, ``second y axis``,
  ``confidence band``). Signatures and docstrings are read from the live objects.
* **Runnable examples** (``glplot/llm/examples/*.py``): fifteen short scripts, each ending in
  ``plt.savefig``.

Pointing a coding agent at it
-----------------------------

A coding agent (Claude Code, Codex, Cursor...) only reads this documentation if something tells it to. Two
generated notes do that, so they name commands that exist in the installed version:

.. code-block:: bash

   python -m glplot.llm agent-instructions >> CLAUDE.md          # or AGENTS.md, .cursor/rules
   python -m glplot.llm skill --write ~/.claude/skills           # a Claude Code skill (SKILL.md)

The note lists the commands above and the rules that prevent the usual failures (``savefig`` rather than
``show()``, animation in ``glplot.animation``, axis limits, the compatibility warnings).

Keeping it true
---------------

The documentation is tested against the code it describes, so it cannot quietly rot:

* every example is **executed** headless in the test suite and must write its figure;
* every ``plt.<name>`` a guide mentions must exist, and so must every function in the "choosing a plot"
  table;
* tables of style presets, categories, examples and unsupported matplotlib names are **generated** from the
  live registries (``{{styles}}``, ``{{categories}}`` ... markers in the Markdown);
* the API index must cover every public function, each one must have a docstring and a category, and a
  list of natural-language queries must find the right function;
* statements the guides make about behaviour (the default output size, the animation methods, the controls
  API) are asserted in ``tests/test_llm_docs.py``;
* ``llms.txt`` is regenerated by ``python -m glplot.llm llms > llms.txt`` and a test fails when it is stale.

Adding a function to ``glplot.pyplot`` needs a docstring and, if its name does not match a rule in
``glplot/llm/apiindex.py``, one word in that file's category table. Adding a guide is a new Markdown file
in ``glplot/llm/topics/`` (``# Title`` then a ``summary:`` line); add its id to ``ORDER`` in
``glplot/llm/guides.py`` to place it.
